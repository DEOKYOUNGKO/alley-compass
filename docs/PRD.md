# PRD: 골목 컴퍼스 (Alley Compass)

## 서울 골목상권 생존 안정성 기반 AI 입지 추천 엔진

| 항목 | 내용 |
|---|---|
| 팀 | AIM |
| 문서 버전 | v1.1 |
| 관련 대회 | 2026학년도 AI(Claude Code) 기반 VIBE CODING 실전활용 경진대회 |
| 서비스 한 줄 정의 | **창업자의 조건에서 출발해 서울 전체 골목상권을 탐색하고, 미래 폐업위험을 기반으로 가장 생존 가능성이 높은 후보지를 추천하는 AI 의사결정 엔진** |

---

# 1. 배경 및 문제 정의

예비 창업자는 입지를 결정할 때 유동인구, 매출, 경쟁점포, 상주인구, 폐업률, 교통 접근성 등 다양한 데이터를 고려해야 한다.

과거에는 전문 상권분석 컨설팅에 높은 비용이 필요했지만, 현재는 서울시 「우리마을가게 상권분석서비스」, 오픈업, 나이스비즈맵 등 무료 또는 저비용 상권분석 서비스가 등장하면서 **상권 정보 자체에 대한 접근성은 크게 개선되었다.**

따라서 골목 컴퍼스가 해결하려는 문제는 단순한 **“상권​*정보의 부족”**이 아니다.

현재 시장에는 다음과 같은 세 가지 의사결정 공백이 남아 있다.

### 1.1 여러 데이터를 사용자가 직접 결합하고 해석해야 한다

서울시 상권 데이터는 유동인구, 매출, 점포, 집객시설, 직장·상주인구 등으로 세분화되어 제공된다.

그러나 각 데이터의 갱신주기가 월간·분기·반기·연간으로 다르고, 예비 창업자가 여러 데이터셋을 상권 코드 기준으로 직접 결합해 의미 있는 판단을 내리기는 어렵다.

즉 데이터는 존재하지만,

> **“그래서​*내 조건에는 어디가 가장 적합한가?”**

에 대한 답으로 변환하는 과정이 부족하다.

### 1.2 현재 상태 분석과 미래 위험 예측은 다르다

기존 상권분석 서비스는 매출, 유동인구, 점포 증가율, 경쟁밀도 등 현재 또는 과거의 상권 상태를 분석하는 데 강점이 있다.

하지만 높은 유동인구나 최근 매출 증가가 반드시 향후 안정적인 영업을 의미하지는 않는다.

골목 컴퍼스는 단순 트렌드 점수가 아니라 과거 상권 데이터를 학습하여,

> **“이​*상권에서 이 업종이 앞으로 얼마나 안정적으로 유지될 가능성이 있는가?”**

라는 예측 문제를 해결한다.

### 1.3 후보지를 정한 뒤 분석하는 서비스는 많지만, 후보지 자체를 찾아주는 과정은 부족하다

기존 서비스는 사용자가 특정 지역 또는 점포를 먼저 선택한 뒤 해당 위치를 분석하는 흐름이 많다.

반면 생애 첫 창업자는 애초에

> “서울 어디에 열어야 할지 모르겠다.”

는 상태에서 시작하는 경우가 많다.

골목 컴퍼스는 **장소가 아닌 창업자의 조건에서 분석을 시작한다.**

```text
기존 방식

후보 지역 선택
      ↓
상권 분석
      ↓
판단
```

```text
골목 컴퍼스

창업자 조건 입력
      ↓
서울 전체 상권 탐색
      ↓
미래 위험 예측
      ↓
후보 Top 5 추천
      ↓
찬성·반대 근거 검증
```

# 2. 핵심 가치 제안

골목 컴퍼스의 핵심 메시지는 다음과 같다.

> **“좋은​*상권과 나에게 좋은 상권은 다르다.”**

유동인구가 가장 많은 상권을 추천하는 것이 아니라,

- 업종
- 보증금 예산
- 타깃 고객층
- 상권 성격
- 비용 민감도
- 성장성 선호
- 생존 안정성 선호

등 사용자의 조건을 반영하여 **서울 전체 후보를 다시 평가한다.**

따라서 골목 컴퍼스는 단순 상권 조회 서비스가 아니라,

> **창업자의 제약조건을 반영한 Location Decision Engine**

을 지향한다.

---

# 3. 경쟁 서비스 대비 포지셔닝

골목 컴퍼스는 기존 상권 서비스의 기능을 대체하기보다 **분석의 시작점과 의사결정 과정에서 차별화**한다.

| 구분 | 기존 상권분석 서비스 | 골목 컴퍼스 |
|---|---|---|
| 분석 시작점 | 특정 지역·점포를 사용자가 먼저 선택 | **창업자의 조건에서 시작** |
| 주요 질문 | “이 지역은 어떤 상권인가?” | **“내​*조건이면 어디가 적합한가?”** |
| 탐색 범위 | 선택 지역 중심 | **서울 전체 골목상권 일괄 탐색** |
| 주요 데이터 | 매출·유동·점포·경쟁 등 | 동일 데이터 결합 + **미래 폐업위험 예측** |
| 결과 | 상권 분석 지표 | **후보 상권 Ranking** |
| 개인화 | 업종·지역 중심 | **업종+예산+타깃+상권성격+우선순위** |
| 설명 | 통계 및 AI 분석 | **추천 Agent + Risk Agent** |
| 근거 검증 | 내부 방식 비공개 또는 별도 검증 없음 | **Verification Agent가 원본 데이터 Tool 호출** |
| 성능 검증 | 모델 평가 방식 비공개인 경우가 많음 | **Temporal Backtest 지표 공개** |
| 조건 변경 | 위치를 다시 설정해 분석 | **조건 변경 즉시 서울 전체 재랭킹** |

### 차별화 논지

골목 컴퍼스의 차별점은 단순히 “AI를 사용한다”는 것이 아니다.

**① 장소가 아니라 사용자 조건에서 시작하고  
② 서울 전체 후보를 탐색하며  
③ 미래 폐업위험을 예측하고  
④ 추천과 반대 근거를 동시에 생성하고  
⑤ 생성된 근거를 다시 원본 데이터와 검증한다.**

# 4. 목표

사용자가 업종·예산·타깃 고객·선호 상권 특성 등을 입력하면,

서울 골목상권 실데이터를 결합한 예측 모델이 **상권×업종별 향후 폐업위험 및 생존 안정성 Score**를 계산한다.

이후 사용자 조건을 반영해 전체 후보를 Ranking하고 상위 5개 상권에 대해 다음 정보를 제공한다.

- 생존 안정성 Score
- 추천 사유
- 반대 사유
- 주요 상권 지표
- 예상 위험요인
- 데이터 출처 및 기준시점
- 모델 신뢰도 정보

최종적으로 예비 창업자가 막연한 검색 대신,

> **“검토할​*가치가 있는 후보 5곳”**

까지 빠르게 범위를 좁힐 수 있도록 하는 것이 목표다.

# 5. Target User

## 5.1 1순위 Persona — 생애 첫 창업·위치 미정형

### 특성

- 30대 중반~40대 초반
- 퇴직·퇴사 후 또는 부업 형태로 첫 창업 준비
- 요식업·생활서비스업 등을 고려
- 보증금 3천만~1억 원 수준의 제한된 초기자본
- 특정 후보지를 아직 결정하지 못함
- 상권분석 전문지식 부족

### 현재 행동

- 유튜브
- 블로그
- 지인 추천
- 부동산 중개인
- 직접 발품
- 무료 상권분석 서비스

등의 정보를 각각 확인한 뒤 감각적으로 종합한다.

### 핵심 Pain Point

> “정보는 많은데 그래서 내가 어디에 열어야 하는지 모르겠다.”

### 핵심 Needs

1. 후보지역을 빠르게 좁혀주는 기능
2. 추천뿐 아니라 위험요인까지 설명
3. 숫자의 출처를 확인할 수 있는 신뢰성
4. 예산이나 업종을 바꿔가며 비교 가능
5. 한정된 자본에서 실패 가능성을 최대한 줄이는 것

### 의사결정 우선순위

1. 생존 안정성
2. 예산 적합성
3. 고객층 적합성
4. 성장 가능성

# 6. 사용자 시나리오

카페 창업을 준비하는 A씨는 아직 서울 어느 지역에 매장을 열지 정하지 못했다.

A씨가 다음 조건을 입력한다.

```text
업종
커피·음료

보증금
5,000만원 이하

타깃
20~30대

상권 성격
유동인구 중심

우선순위
생존 안정성
```

시스템은 서울 전체 골목상권을 탐색하고 상위 5개 후보를 제시한다.

예:

```text
1위 문래동 ○○골목
생존 안정성 81점

추천 근거
+ 최근 4분기 업종 매출 상승
+ 동종업종 밀도 서울 평균 이하
+ 입력 예산 범위 내

반대 근거
- 21시 이후 유동인구 감소
- 지하철역과의 접근성이 상위 상권보다 낮음
```

A씨가 다음과 같이 질문한다.

> “카페 말고 세탁소는?”

시스템은 데이터를 다시 수집하는 대신 기존 결합 데이터와 학습된 모델을 이용해 업종 조건을 변경하고 전체 상권을 즉시 재랭킹한다.

또한,

> “예산을 3,000만원으로 낮추면?”

이라고 하면 예산 초과 후보의 적합도가 감소하며 새로운 Top 5가 생성된다.

# 7. 예측 문제 정의

## 7.1 MVP 모델의 예측 대상

MVP에서는 개별 점포의 생존을 직접 예측한다고 표현하지 않는다.

서울시 공개데이터의 기본 분석 단위에 맞춰,

> **상권 × 업종 단위의 향후 폐업위험 및 생존 안정성**

을 예측한다.

### Input

특정 시점 t의 상권×업종 특징:

- 유동인구
- 연령별 유동인구
- 상주인구
- 직장인구
- 점포수
- 개업률
- 폐업률
- 동종업종 밀도
- 추정매출
- 매출 성장률
- 집객시설
- 교통 접근성
- 경쟁강도
- 기타 파생변수

### Target

t 이후 일정 기간 동안 해당 상권×업종에서 발생하는 **폐업위험 또는 영업 안정성**을 Label로 구성한다.

구체적인 Label 정의는 데이터 EDA 이후 확정한다.

후보:

1. 다음 연도 폐업률 증가 여부
2. 향후 N분기 폐업률 임계치 초과 여부
3. 향후 일정 기간 점포수 유지 여부
4. 폐업률 및 매출 안정성을 결합한 생존 안정성 Label

### Output

모델의 raw probability를 그대로 개인 점포의 생존확률로 해석하지 않고,

> **상권×업종 생존 안정성 Score**

로 서비스에 제공한다.

향후 개별 점포 cohort 데이터를 확보하여 실제 생존기간 추적이 가능해질 경우 **3년 생존확률 모델**로 확장한다.

| F-11 | 상세 분석 | 후보별 매출·유동·경쟁·폐업 추세 시각화 |

# 9. Multi-Agent Architecture

골목 컴퍼스는 모든 작업을 LLM에 맡기지 않는다.

각 작업의 특성에 따라 **결정론적 코드, ML 모델, LLM Agent의 역할을 명확히 분리**한다.

```text
[사용자 조건]
      ↓

① Data Layer
Pandas / Python
      ↓

② Prediction Layer
LightGBM
      ↓

③ Recommendation Agent
Claude
      ↓

④ Risk Agent
Claude
      ↓

⑤ Verification Agent
Claude
      ↓
Data Validation Tools
      ↓

[Verified Recommendation]
```

# 10. Agent 역할

## 10.1 Recommendation Agent

입력:

- 모델 Ranking
- 상권 Feature
- 사용자 조건

역할:

- 추천 후보의 긍정적 근거 추출
- 사용자의 우선순위에 맞게 설명
- 핵심 수치를 자연어로 변환

예:

> “해당 상권은 최근 4개 분기 커피·음료 매출이 상승했고, 동종업종 밀도는 서울 골목상권 평균보다 낮습니다.”

---

## 10.2 Risk Agent

Recommendation Agent와 독립적으로 동일 후보를 분석한다.

역할:

- 경쟁 과포화
- 매출 감소
- 폐업 증가
- 특정 시간대 유동 공백
- 예산 초과
- 교통 접근성 부족

등 추천에 반대되는 Evidence를 우선 탐색한다.

목표는 Recommendation Agent의 결론을 따라가는 것이 아니라 **추천 후보의 취약점을 적극적으로 탐색하는 것**이다.

---

## 10.3 Verification Agent

Verification Agent는 AI가 생성한 설명을 다시 AI의 직감으로 검증하지 않는다.

대신 생성된 자연어에서 **검증 가능한 Claim을 추출하고 적절한 데이터 검증 Tool을 선택·호출한다.**

예:

```text
생성 문장

"문래동의 20대 유동인구는
서울 골목상권 상위 8%입니다."
```

Verification Agent:

```text
Claim 추출

상권 = 문래동
Metric = 20대 유동인구
Claim = 상위 8%
```

이후 Percentile Calculation Tool을 호출한다.

```text
실제 계산

상위 9.3%
```

검증 결과:

```text
FAIL

"상위 8%" → 데이터와 불일치
```

Agent는 해당 문장을 반려하고 재생성을 요청한다.

최종 표현:

> “서울 골목상권 기준 상위 약 10% 수준입니다.”

### 핵심 원칙

> **AI가 설명하고, AI가 검증 절차를 지휘하며, 숫자는 코드가 증명한다.**

---

# 11. Verification Tools

Verification Agent가 호출할 수 있는 Tool은 다음과 같다.

### Data Lookup Tool

특정 상권·업종·기간의 원본 값을 조회한다.

### Percentile Tool

특정 Feature가 서울 전체 후보 중 어느 Percentile인지 계산한다.

### Budget Validator

예상 보증금 또는 비용이 사용자 입력 한도 내인지 검증한다.

### Assertion Validator

생성 문장에 포함된 수치와 계산 결과가 허용 오차 범위 내에서 일치하는지 판단한다.

# 13. 데이터 결합 원칙

각 데이터셋은 동일한 시점에 갱신되지 않는다.

따라서 단순히 가장 최신 파일끼리 Join하지 않고 **Feature별 기준시점을 기록한다.**

각 Row는 다음 Metadata를 포함한다.

```text
상권 코드
업종 코드

유동인구 기준시점
매출 기준시점
점포 기준시점
집객시설 기준시점
직장인구 기준시점
상주인구 기준시점
```

결합 Pipeline은 기준시점 차이가 허용범위를 넘는 경우 Warning을 발생시킨다.

또한 데이터 공간단위 또는 상권 코드 체계가 연도별로 변경되는 경우 동일 지역이 잘못 연결되지 않도록 별도의 Mapping 단계에서 처리한다.

# 15. Model Validation

Random Train/Test Split만 사용하지 않는다.

상권 예측은 미래 정보를 이용한 Data Leakage 가능성이 있으므로 **시간 기반 Temporal Split**을 원칙으로 한다.

예:

```text
과거 기간
Train

↓

그 이후 기간
Validation

↓

가장 최근 기간
Test
```

미래 시점의 Feature가 과거 Label 예측에 포함되지 않도록 Feature Timestamp를 엄격하게 관리한다.

### 주요 평가 지표

#### ROC-AUC

생존 안정 상권과 위험 상권을 얼마나 잘 Ranking하는지 평가.

#### PR-AUC

폐업위험 Class가 적은 경우 Class Imbalance 상황에서 성능을 평가.

#### Brier Score

예측 Probability와 실제 결과 사이의 오차 측정.

#### Calibration Curve

모델이 70% 위험이라고 예측한 집단에서 실제 위험 발생률도 유사한지 평가.

#### Top-K Evaluation

모델이 추천한 Top 5·Top 10 후보의 실제 미래 안정성이 전체 평균보다 유의하게 높은지 평가.

---

# 16. 사용자 Ranking Logic

최종 Ranking은 예측 모델 결과만으로 결정하지 않는다.

```text
Model Survival Stability
        +
Budget Fit
        +
Target Customer Fit
        +
User Preference
        ↓
Personalized Ranking
```

예를 들어 생존 안정성은 높지만 보증금이 사용자의 예산을 크게 초과한다면 최종 Ranking이 낮아진다.

반대로 절대적인 유동인구는 다소 낮더라도,

- 예산 내
- 경쟁밀도 낮음
- 폐업 추세 안정
- 타깃 고객층 적합

이라면 더 높은 Ranking을 받을 수 있다.

# 18. 비기능 요구사항

## 정확성

LLM은 원본 데이터 집계나 확률 계산을 직접 수행하지 않는다.

Pandas 및 ML Model이 계산한 결과만 사용한다.

## Hallucination Control

AI가 생성한 수치·사실 Claim은 Verification Agent가 검증 Tool을 호출하여 원본 데이터와 대조한다.

검증 실패 시 최종 사용자에게 노출하지 않는다.

## 성능

일반적인 추천 요청은 30초 이내 반환을 목표로 한다.

조건 변경 기반 재랭킹은 가능한 한 수 초 수준을 목표로 한다.

## Explainability

사용자가 최종 Score만 보는 것이 아니라 해당 결과를 만든 주요 Feature와 찬반 Evidence를 확인할 수 있어야 한다.

## Data Traceability

각 숫자에 대해

- 출처
- 데이터셋
- 기준시점

을 추적할 수 있도록 한다.

## 라이선스

공공데이터 사용조건을 준수하고 화면 및 Report에 출처를 명시한다.
